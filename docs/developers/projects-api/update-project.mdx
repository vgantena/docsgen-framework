# Update a project

<ApiEndpoint method="PATCH" path="/v1/projects/{id}">Renames, archives, or restores a project.</ApiEndpoint>

## Overview

Applies a partial update to a project. This is also the safe alternative to [deletion](/developers/projects-api/delete-project): archiving makes a project read-only while keeping all of its data, and archived projects can be restored at any time. On a status change, a [webhook event](/developers/webhooks) fires: `project.archived` on archive, `project.restored` on restore.

<Badge variant="admin">Admin role</Badge> <Badge variant="info">All plans</Badge>

## Request

### Path parameters

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | string | Yes | Project identifier, for example `proj_8fK2m`. |

### Body parameters

Send only the fields you want to change:

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | No | New display name, 1–120 characters. Unique within the workspace. |
| `status` | string | No | `archived` to archive, `active` to restore. |

### Headers

| Header | Value |
| --- | --- |
| `Content-Type` | `application/json` |

## Response

`200 OK` — the updated [project object](/developers/projects-api/#the-project-object):

```json
{
  "id": "proj_8fK2m",
  "name": "Quarterly report",
  "status": "archived",
  "members": 4,
  "created_at": "2026-07-01T09:30:00Z",
  "updated_at": "2026-07-27T08:12:41Z"
}
```

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Unique identifier, prefixed `proj_`. Stable for the project's lifetime. |
| `name` | string | Display name, 1–120 characters. Unique within the workspace. |
| `status` | string | `active` or `archived`. Archived projects are read-only. |
| `members` | integer | Count of workspace members with access. |
| `created_at` | string | ISO 8601 creation timestamp (UTC). |
| `updated_at` | string | ISO 8601 timestamp of the last change (UTC) — set to the moment of this update. |

## Status and error codes

| Status | Code | When |
| --- | --- | --- |
| `200` | — | Project updated. |
| `400` | `validation_failed` | Empty body, unknown field, invalid `status` value, or `name` outside 1–120 characters. |
| `401` | `unauthenticated` | Missing, malformed, or revoked API key. |
| `403` | `insufficient_role` | Key's role is below Admin. |
| `404` | `resource_not_found` | No project with this `id` — including deleted projects. |
| `409` | `name_conflict` | The new `name` is already used by another project in the workspace. |
| `422` | `project_limit_reached` | Restoring would exceed the Free plan's 3-active-projects limit. |
| `429` | `rate_limited` | Too many requests — wait for `X-RateLimit-Reset`. |
| `5xx` | `server_error` | Server problem — retry with exponential backoff. |

## Business rules

- Archived projects are **read-only**: task and file writes are rejected until the project is restored with `"status": "active"`.
- Restoring counts against the Free plan's 3-active-projects limit — restore fails with `422 project_limit_reached` when the limit is already reached.
- Archiving fires `project.archived` and restoring fires `project.restored` to all [webhook subscriptions](/developers/webhooks); renames update `updated_at` but fire no event.
- Rename uniqueness is case-insensitive, same as [create](/developers/projects-api/create-project).
