# Webhooks

Webhooks push events to your endpoint the moment they happen — no polling. Configure them in **Settings** → **Webhooks**.

## Available events

| Event | Fires when |
| --- | --- |
| `project.created` | A project is created. |
| `project.archived` | A project's status changes to `archived`. |
| `project.deleted` | A project is permanently deleted. |
| `member.invited` | A workspace invitation is sent. |
| `member.joined` | An invitation is accepted. |

## Delivery format

Each delivery is an HTTPS `POST` with a JSON body:

```json
{
  "id": "evt_2mQ7x",
  "type": "project.created",
  "created_at": "2026-07-26T10:15:00Z",
  "data": {
    "id": "proj_8fK2m",
    "name": "Quarterly report",
    "status": "active",
    "members": 1,
    "created_at": "2026-07-26T10:15:00Z",
    "updated_at": "2026-07-26T10:15:00Z"
  }
}
```

`data` always carries the full [project object](/developers/projects-api/#the-project-object) as of the moment the event fired — for `project.deleted`, that's its final state.

Your endpoint must respond with a `2xx` status within 10 seconds. Anything else counts as a failed delivery.

## Verify signatures

Every delivery is signed so you can reject forged requests. The `X-Signature` header contains an HMAC-SHA256 of the raw body, keyed with your webhook secret:

<Tabs groupId="lang">
<TabItem value="python" label="Python">

```python
import hashlib
import hmac

def verify(secret: str, body: bytes, signature: str) -> bool:
    expected = hmac.new(secret.encode(), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(expected, signature)
```

</TabItem>
<TabItem value="js" label="JavaScript">

```javascript
const crypto = require('node:crypto');

function verify(secret, rawBody, signature) {
  const expected = crypto.createHmac('sha256', secret).update(rawBody).digest('hex');
  return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(signature));
}
```

</TabItem>
</Tabs>

:::warning
Compute the HMAC over the **raw** request body, before any JSON parsing — re-serialized JSON may differ byte-for-byte and fail verification.
:::

## Retries

Failed deliveries retry with exponential backoff: 1 minute, 5 minutes, 30 minutes, 2 hours, then hourly for up to 24 hours. Deliveries are at-least-once — use the event `id` to deduplicate.
